# ORM

## Contexto

El backend original usa JPA/Hibernate sobre MySQL con un schema heredado y entidades que ya reflejan nombres de tablas reales.

## Decisión

Se adopta TypeORM para la API NestJS.

## Alternativas consideradas

- Prisma
- Sequelize
- acceso SQL manual

## Consecuencias

- Mejor encaje con el schema heredado y el estilo modular de NestJS.
- Se pueden mapear tablas existentes con menor fricción.
- La migración de dominio puede avanzar por módulos sin reescribir todo el acceso a datos.
